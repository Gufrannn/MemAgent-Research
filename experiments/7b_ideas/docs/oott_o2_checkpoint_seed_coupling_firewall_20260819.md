# OOTT O2 checkpoint seed-coupling firewall

O2 remains unauthorized and this firewall adds no rollout, GPU work, or queue entry. If existing gates later unlock stochastic T25↔T200 O2, the primary uses checkpoint-specific, non-overlapping independent seed namespaces. Each stable example is averaged over exactly four seeds within each checkpoint before the example-level contrast. Seed repeats do not increase independent n and cannot certify an individual example's sign.

The same integer seed does not define a natural trajectory identity across policies. A CRN view is permitted only with corrected per-trajectory seeds, `BCI=PASS_COUPLED`, a prefrozen coupling manifest, and a namespace disjoint from both primary namespaces. Its sole role is implementation-coupling sensitivity. It cannot be selected because a pilot had lower variance, a narrower interval, or a preferred direction, and it cannot be called an individual or causal paired effect.

If primary and CRN directions disagree, the fixed classification is `COUPLING_SENSITIVE_STOCHASTIC_TRANSPORT`; neither view may be selected after the fact. Exact Bernoulli enumeration with marginals `.8` and `.6` keeps mean difference `.2` while difference variance is `.16` under comonotone coupling, `.40` under independence, and `.56` under countermonotone coupling. Coupling changes Monte Carlo variance and finite-sample appearance, not the policy-marginal estimand.

`analysis/validate_oott_o2_seed_coupling_20260819.py` is outcome-free. The committed config remains `O2_NOT_AUTHORIZED`.
