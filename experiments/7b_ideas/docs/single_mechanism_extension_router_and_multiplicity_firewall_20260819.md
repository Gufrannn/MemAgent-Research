# Single-mechanism extension router and multiplicity firewall

Before any CWI, SMIC/HMIC, portability, or successive-refinement outcome exists, freeze one low-dimensional evidence signature using only C0 execution, C1 SMSB serialization, C2 Tetrad utilization, C3 Triangle/BOT structure, C4 exact NOOP/per-update obligations, the budget frontier, pre-extension claim need, and construct-only yield. Candidate effects, p-values, checkpoint winners, and post-outcome narratives are forbidden inputs; `candidate_extension_outcome_accessed` must be false.

Each candidate is mechanically `true`, `false`, or `pending`. Missing, invalid, and pending facts remain pending and cannot masquerade as failures that trigger another candidate. Exactly one true yields `SELECT_ONE`; zero true with pending yields `PENDING_NO_EXTENSION`; zero true without pending yields `NO_MECHANISM_EXTENSION`; multiple true yields `AMBIGUOUS_NO_EXTENSION`.

Ambiguity may only be resolved by an outcome-free construct discriminator, followed by a newly frozen manifest. Candidate pilot effects cannot break ties. A negative selected extension cannot switch to a runner-up on the same S128. If portability is selected, CWRTD and the reader-method matrix are derived members of one data family, not additional independent mechanisms.

The router outputs a canonical `decision_input_sha256`. It is research-design governance, not a significance correction or algorithm. It never authorizes training, step 400, C256, parallel runners, or a mandatory extension. The current default is `PENDING_NO_EXTENSION`.
