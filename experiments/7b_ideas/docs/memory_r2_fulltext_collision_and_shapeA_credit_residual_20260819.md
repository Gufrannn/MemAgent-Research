# Memory-R2 full-text collision and the residual Shape A credit claim

Memory-R2 (arXiv:2605.21768v1) observes that memory actions change the agent's future effective environment, so global GRPO comparisons across trajectories whose memory states have diverged are contaminated. LoGo-GRPO retains a global branch and locally rerolls a session multiple times from one cached pre-session anchor, using group-relative local reward alongside global trajectory credit. It also uses an 8→16→32-session curriculum.

Generic blocked within-state comparison, same-anchor local rerollout, global/local memory credit, CERC as a method, and the short-to-long curriculum are permanently unavailable as title-level novelty. Implementing them with another group key or centering formula is a Memory-R2-adjacent reproduction, not a new method.

Memory-R2 does not fix the same materialized candidate. Each rerollout regenerates the fact-extractor candidate and manager action; its `NO OPERATION` is a newly generated manager action. This differs from freezing candidate text and writer randomness, then experimentally executing exact `commit(candidate)` versus exact discard/retain/NOOP under a shared suffix.

The residual Shape A scope is therefore narrow: exact same-materialized-candidate commit versus exact discard/NOOP shared-suffix execution effect; outcome-independent structural effect modification; and a linked witness to information discarded by the actual GRPO estimator. It is an identification/measurement claim, not a general fair-credit or local-rerollout algorithm.

A future unique rerollout-like candidate would need an equal writer mask, local group size, reward information, rollout/token budget, and scale Memory-R2-like baseline, plus both evidence-ledger and single-extension-router authorization. The current suite only records a schema/validator and refuses LoGo-GRPO implementation, training, curriculum, or longer runs.

Primary source: [Memory-R2, arXiv:2605.21768v1](https://arxiv.org/abs/2605.21768).
