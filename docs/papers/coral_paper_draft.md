# Refresh Before You Consume: Occupancy-Ordered Policy Optimization for Self-Written Memory Agents

**Scientific checkpoint (2026-08-22): REFRAME; independently re-audited E0 GO; E1 execution and final framing review pending.** This is a preregistered paper program, not a positive-results report. Bracketed results are placeholders. The rejected high-confidence COSI optimizer remains documented separately and is not renamed or revived here.

## Abstract (206 words)

Recurrent text-memory agents use one language model to write a compact memory and later consume that self-written text to answer. Standard sequence policy optimization estimates writer-token and answer-token gradients on the same pre-update trajectories. A writer update, however, changes the distribution of memories that the answer role will observe, so its simultaneously estimated gradient can target an occupancy that disappears immediately after the update. We study this specific writer-to-terminal-answer coupling and introduce **Cross-Occupancy Role-Alternating Learning (CORAL)**: odd updates optimize non-final memory-writing tokens; strict weight synchronization then materializes fresh memories on the next ordinary rollout; even updates optimize only terminal-answer tokens on that refreshed occupancy. Both masks update one shared language model, and no inactive-role trust-region guarantee is claimed. In a recurrent one-bit MDP, exact enumeration of the frozen mean-centered GRPO estimator shows that a simultaneous shared-parameter update decreases return while the occupancy-refreshed update increases it. A preregistered mechanism test holds proposal weights fixed and compares terminal-answer projected gradients under cached versus regenerated memories, separating occupancy response from shared-parameter drift, same-batch gradient conflict, memory length, and numerical replay noise. CORAL uses the same reward, data order, generated-trajectory budget, tokenizer, and fresh Qwen2.5-7B base as Original, while explicitly reporting its lower per-role update exposure. Performance at updates 5–25 is **[not yet run]**; training remains locked unless real single-update occupancy response and independent paper review pass.

## 1. Introduction

Long-context language agents increasingly externalize state into text. MemAgent is a particularly clean instance: after reading each chunk, one language model overwrites a bounded memory; after the final chunk, the same model answers from the memory it has created. This architecture can generalize beyond its training length, but it also creates an unusual reinforcement-learning loop. The policy does not merely act *in* a state distribution. Its earlier tokens write a string that becomes a later prompt, and its later tokens consume that string. Updating the policy changes both the consumer and the distribution of textual states being consumed.

The practical optimizer does not expose that distinction. Original recurrent GRPO generates a complete trajectory with checkpoint \(\theta_k\), attaches the outcome advantage to all generated tokens, and updates the shared model using memory-writing and terminal-answer losses from that same trajectory. This is a legitimate on-policy estimate at \(\theta_k\). The issue is finite-step ordering: the terminal-answer gradient is evaluated on memories sampled before the writer part of the same update. If the writer update materially changes memory occupancy, the answer gradient can be locally correct for old memories yet wrong for the memories that the updated model will actually write. PPO clipping, token KL, or a sequence-level likelihood ratio controls action-distribution movement on sampled prompts; none directly measures whether the terminal-answer direction changes after the self-written prompt is regenerated.

This is not a generic claim that policy gradients ignore occupancy. The policy-gradient theorem already integrates over the policy's state occupancy, and performance-difference and simulation lemmas characterize distribution shift. Nor is alternation itself new: block-coordinate optimization and HAPPO-style sequential multi-agent updates are established. The residual is narrower. In a recurrent text agent, one *shared-parameter* model produces a discrete, materialized prompt and later consumes it; the environment can regenerate that prompt between ordinary updates at no additional trajectory count. We ask whether ordering role-masked updates around that real regeneration changes the gradient that matters.

CORAL implements the smallest intervention that tests this idea. At update 1 it applies the unchanged GRPO objective only to non-final memory-writing responses. Crucially, masking does **not** renormalize by the shorter active-role token count: the loss retains Original's full-response token denominator. Inactive rows are removed from the forward pass only after their token count is frozen into that denominator. A deterministic pre-dispatch permutation gives every data-parallel rank both roles, preventing role-empty shards without changing any advantage or row identity. The existing audited actor-to-vLLM synchronization then installs the new shared weights. The next normal on-policy rollout regenerates every memory. At update 2, CORAL applies the GRPO objective only to the final answer response, again with the Original denominator. This writer/answer schedule repeats through update 25. “Answer” means exactly the terminal response selected by the existing `final_mask`; the method does not claim to refresh every intermediate writer-to-writer boundary. Both masks update the same \(\theta\), so a writer-active step can alter answer behavior and vice versa. CORAL makes no fictitious claim that the inactive function is held fixed. In particular, we removed a behavior-point inactive KL penalty after observing that, with the frozen one-epoch protocol, its value and first derivative can be zero for the first and possibly only optimizer minibatch.

The central scientific object is the **frozen-projection response of the terminal-answer gradient to writer occupancy**. Starting from source checkpoint \(\theta\), we take an authenticated writer-only proposal \(\theta_W\). The source-policy terminal actions, rewards, and advantages are discarded. After synchronizing \(\theta_W\), E1 constructs two terminal prompts: one injects the cached old materialized memory and the other injects memory regenerated by \(\theta_W\). Both terminal answers are newly sampled from the same fixed proposal policy with the same branch-coupled terminal request seeds, and each branch independently recomputes reward and GRPO advantage. Actual-loss terminal gradients are then computed at the same \(\theta_W\). Thus the total contrast includes the downstream action/reward response mediated by changing self-written memory, but not source-versus-proposal terminal sampling or parameter drift. Duplicate cached-memory backpropagations establish the numerical floor. The primary estimand is explicitly the norm/cosine of four preregistered, deterministic, nonlinearly basis-separated 256-bucket distributed CountSketches (concatenated and norm-scaled), not the unprojected full-gradient norm; a two-rank oracle and projection-size calibration are E1 infrastructure gates. E1 uses eight real writer proposals at odd updates 1--15, each on four previously unused step-independent dataset roots with two trajectory replicas. The 32 root clusters are measured by the trainer itself and sealed against Gate-A weight-sync records and full actor source/proposal inventories; no external JSON measurement is accepted.

This identification is important because several cheaper explanations are plausible. Perhaps writer and answer gradients merely conflict on one batch, in which case PCGrad or role masking without fresh rollout should suffice. Perhaps answer sensitivity is explained by longer or shorter memories, in which case a length control is enough. Perhaps the memory bottleneck is too lossy, but that is a representation/rate-distortion problem rather than an update-order problem. Perhaps robust or conservative policy optimization already controls the relevant shift, in which case CORAL adds no standalone insight. The E1 gate is designed to eliminate the paper under any of those outcomes rather than reinterpret a null result.

Budget accounting is equally explicit. At 25 rollouts, Original applies both role losses 25 times, whereas CORAL applies 13 writer-active and 12 terminal-answer-active updates. Thus CORAL is matched to Original in generated trajectories, training examples, reward calls, data order, and anchor count, but not in per-role gradient exposure. We therefore require three controls: Original at 25 rollouts; a masked half-exposure control that does not order updates around fresh occupancy; and a role-exposure-matched CORAL control (50 updates or an equivalent preregistered token-gradient budget). Generated tokens, forward/backward FLOPs, synchronization cost, and wall time are reported separately. The primary frozen T5–T25 curve remains the 25-rollout comparison; exposure matching is an attribution experiment, not a replacement estimand.

The fixed data order creates another recognizable threat: a strict odd/even schedule correlates role with batch parity and training time. The primary seed is frozen for comparability, so this cannot be wished away. A reversed terminal-answer-first schedule and counterbalanced additional seeds are mandatory before a full empirical claim. At T5, parity-stratified reward and token statistics are health diagnostics only. A result that disappears under reversal or counterbalancing is classified as a schedule/data interaction, not occupancy evidence.

Our paper program has four layers. First, a shared-parameter recurrent formulation isolates the parameter-response and occupancy-response terms omitted by a stale terminal-answer direction. Second, an exact enumerated recurrent MDP demonstrates a finite-step reversal under the same group-normalized outcome-gradient structure used by GRPO. Third, an authenticated cached-versus-refreshed gradient protocol directly identifies the real-model occupancy response without using gold answers, future chunks, or the frozen S128 outcome as a training oracle. Fourth, conditional on those gates, fresh Qwen2.5-7B training compares CORAL and mechanism controls against the already authenticated Original checkpoints at updates 5, 10, 15, 20, and 25.

Our intended contributions are:

1. **Problem and theory.** We formalize writer-to-terminal-answer occupancy staleness for a single shared-parameter recurrent text policy and separate it from generic off-policy sampling and same-batch gradient conflict.
2. **Algorithm.** We introduce a role-masked, rollout-refreshed update order that activates from update one, uses no additional generated trajectory in the primary budget, and is exact about its 13/12 role exposure.
3. **Identification and systems.** We provide a fixed-weight cached-versus-regenerated memory gradient test, authenticated seeds/checkpoints/projections, strict vLLM weight synchronization, deterministic identities, append-only ledgers, and resume/audit closure.
4. **Empirics.** If E1 passes, we will report matched fresh-base multi-anchor results, direct controls for PCGrad, masking, parity, exposure, and sequence-level optimization, plus an external recurrent-memory confirmation. All values remain **[pending H20 execution]**.

## 2. Problem formulation and propositions

Let \(x\sim\mathcal D\) be a root. A shared policy \(\pi_\theta\) produces memory responses \(M_{1:T}\), where each \(M_t\) is materialized into the next prompt, and a terminal answer \(A\). The return is \(R(x,M_{1:T},A)\). Let \(d^W_\theta\) denote the distribution of terminal prompts induced by all writer turns under \(\theta\). Using the existing final mask, define role-conditioned outcome-gradient expectations

\[
g_W(\theta)=\mathbb E_{\tau\sim\pi_\theta}\!\left[\widehat A(\tau)\sum_{u\in W}\nabla_\theta\log\pi_\theta(y_u\mid h_u)\right],
\]

\[
g_A(\vartheta;d)=\mathbb E_{h\sim d,\,A\sim\pi_\vartheta(\cdot\mid h)}\!\left[\widehat A(h,A)\sum_{u\in A}\nabla_\vartheta\log\pi_\vartheta(y_u\mid h_u)\right].
\]

Both are vectors in the same parameter space. A simultaneous masked update uses \(g_W(\theta)+g_A(\theta;d^W_\theta)\). A CORAL pair uses

\[
\theta_W=\theta+\eta_W g_W(\theta),\qquad
\theta_C=\theta_W+\eta_A g_A(\theta_W;d^W_{\theta_W}),
\]

where the second expectation is estimated from the next ordinary rollout. Actual training uses consecutive outcome-blind minibatches from the frozen stream, so the equation is a population update and not a claim of paired roots.

**Proposition 1 (shared-parameter response decomposition).** Assume \(g_A(\vartheta;d^W_\phi)\) is Fréchet differentiable in evaluation weights \(\vartheta\) and writer-induced occupancy parameter \(\phi\). For \(\delta=\theta_W-\theta\),

\[
g_A(\theta+\delta;d^W_{\theta+\delta})-g_A(\theta;d^W_\theta)
=\left[D_\vartheta g_A+D_\phi g_A\right]_\theta\delta+O(\|\delta\|^2).
\]

The fixed-proposal E1 contrast

\[
g_A(\theta_W;d^W_{\theta_W})-g_A(\theta_W;d^W_\theta)
\]

isolates the occupancy-response component from direct shared-parameter drift. This is the precise estimand; same-batch writer/answer cosine does not identify it.

**Proposition 2 (finite shared-policy GRPO reversal).** In the executable one-bit recurrent MDP, one scalar \(\theta\) parameterizes writer logit \(10\theta-4\) and role-conditioned answer logits \(-9\theta-3\) and \(-4\theta-3\). Reward is one iff answer equals materialized memory. At \(\theta=0.6\), step size 4.7, and group size 2, exact enumeration of all ordered rollout pairs with the accepted Original's mean-centered outcome advantages (`grpo_use_adv=False`) gives old return 0.1231364. Both simultaneous and role-masked directions use the same two-token Original `token-mean` denominator, so each one-token role carries scale 1/2. The simultaneous shared-parameter update gives 0.0565356, while a writer step followed by regenerated occupancy and an answer step gives 0.9404810. The terminal-answer gradient changes sign. This proposition establishes possibility, not prevalence or an asymptotic advantage.

**Proposition 3 (testable first-order advantage condition).** Let \(g_A^{old}=g_A(\theta_W;d^W_\theta)\) and \(g_A^{new}=g_A(\theta_W;d^W_{\theta_W})\). Under \(L\)-smooth return, the difference between fresh- and cached-occupancy answer steps has first-order term \(\eta_A\langle\nabla J(\theta_W),g_A^{new}-g_A^{old}\rangle\) and remainder bounded by \(L\eta_A^2(\|g_A^{new}\|^2+\|g_A^{old}\|^2)/2\). CORAL can only have a mechanism advantage when the measured response is non-negligible and favorably aligned. E1 measures response magnitude; performance and alignment are falsified by the T5 controls. No monotonic-improvement or global-safety guarantee follows.

A standalone contribution exists only if the conjunction is empirically necessary: real single writer proposals must materially change terminal-answer gradients at fixed weights; the signal must exceed duplicate noise and survive length/turn and nonconflicting-cosine controls; and fresh-rollout ordering must outperform same-mask, PCGrad, reversed-schedule, and exposure-matched controls. Otherwise CORAL is merged as a diagnostic in a broader recurrent-policy-optimization paper.

## 4. Frozen experiments and failure criteria

### E0 and E1 before training

- **E0:** exact enumeration, shared \(\theta\), stochastic writer, materialized state, terminal consumer, group-size-2 mean-centered outcome advantages matching `grpo_use_adv=False`, and the exact same two-token denominator for Original and both CORAL phases. Required: simultaneous return drops by at least .03, CORAL rises by at least .03, and the answer gradient flips sign. Current executable status: PASS after normalization correction and independent re-audit.
- **E1 actual producer:** an isolated fresh-base diagnostic executes updates 1--15 with save-every-step but is never reused as Method initialization. At each of the eight writer-active odd updates, the trainer caches the four b4 roots, applies the actual writer loss, authenticates actor-to-vLLM synchronization, and regenerates the same roots with the same two trajectory seeds. It then discards both branches' existing final actions and samples new terminal answers at proposal weights from the cached-memory and refreshed-memory prompts using identical terminal request seeds. Each branch recomputes reward and GRPO advantage before cached, duplicate-cached, refreshed-answer, and cached-writer actual-loss backward passes. The optimizer step inventory must be unchanged by every measurement.
- **E1 authentication:** every proposal binds exact Git commit, a frozen hash for four nonlinearly basis-separated 256-bucket CountSketch maps, root and seed inventories, prompt/memory token hashes, sampled live-weight digests, and complete on-disk source/proposal actor inventories. A two-rank NCCL oracle must match an unsharded tiny-model gradient, close the Original full-denominator gradient into writer plus answer terms, and keep projected-norm error within 10% on a preregistered collision-heavy 1,000,003-coordinate vector. The sealer accepts only the eight trainer-owned exclusive receipts at steps 1,3,...,15 and the hash-chained Gate-A ledger.
- **E1 PASS:** 32 never-reused roots are nested four per writer proposal, so the inferential units are the eight proposal means. The overall mean symmetric response \(2\|g_A^{new}-g_A^{old}\|/(\|g_A^{new}\|+\|g_A^{old}\|)\) must be ≥.15 and the preregistered proposal-cluster LCB (mean of eight proposal means minus \(t_{.975,7}=2.365\) proposal-level standard errors) ≥.05; at least eight length-matched roots must average ≥.12; ≥25% must show response ≥.15 despite nonnegative same-batch writer/answer cosine; at least four of eight proposals must average ≥.15; duplicate relative response must be ≤1e-6. These are mechanism thresholds, not a policy-safety confidence claim.
